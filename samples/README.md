# samples/

Before/after pairs, one per mockup and mode, so the output can be judged without installing
ImageMagick and running the tool.

| Mockup | Mode | Before / after |
|--------|------|----------------|
| mug | arc | `mug-arc-before.png` / `mug-arc-after.png` |
| bottle | displace | `bottle-displace-before.png` / `bottle-displace-after.png` |
| tin | displace | `tin-displace-before.png` / `tin-displace-after.png` |

## How these were produced

These come from `tools/make-mockups.py`, a small Python/Pillow reference implementation of
the same pipeline. They are **not** captures of `curve-text.sh` output: the machine they
were generated on had no ImageMagick installed, and inventing output to fill the table would
have been worse than saying so plainly.

The Python path follows the same four steps as the shell tool (flat label first, then an arc
or displacement warp, then a blend composite), so the images are representative of what the
pipeline does. Exact pixels will differ. ImageMagick's `-distort Arc` resamples with a real
filter rather than nearest-neighbour, `-compose displace` treats edges differently, and the
shell tool applies `opacity` and `level_floor` per item.

There is no `cylinderize` sample, because that mode shells out to Fred Weinhaus'
`cylinderize.sh`, which is not bundled here. The tin uses `displace` with a stronger curve
instead.

To replace these with genuine tool output, install ImageMagick and `jq`, then:

```bash
./curve-text.sh items.json out/
cp mockups/mug.png          samples/mug-arc-before.png
cp out/00_fresh-roast-daily.png samples/mug-arc-after.png
```

## Naming

```
samples/<mockup>-<mode>-before.png
samples/<mockup>-<mode>-after.png
```

`<mockup>` is the mockup stem from `mockups/` (`mug`, `bottle`, `tin`). `<mode>` is the
`mode` value from the item. "Before" is the untouched mockup, not a flat-text render: the
comparison that matters is product-with-nothing against product-with-curved-text, at the
same dimensions so the two can be flipped between or diffed.

Before committing a replacement:

- Downsample to something reasonable for a README, e.g. `-resize 900x`. Full-resolution
  renders do not belong in git.
- Strip metadata: `magick in.png -strip out.png`.
- Record the item that produced it. The run manifest written by `lib/log.sh` has the exact
  parameters; paste the relevant line into the commit message so the sample traces back to
  its input.

Everything else generated by a run stays in `out/` and is gitignored.
